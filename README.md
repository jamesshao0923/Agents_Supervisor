面向 macOS 的长程 Agent 任务监督管理器。将目标转成可验收契约，监督执行、验证、修复与交付。首接 Codex，后续保留其他执行器接口。

**当前阶段：P5 需求准入、计划与文本记忆已完成真实运行与独立验收。** P4 独立验证器此前已通过真实运行、桌面操作及独立门禁审查。 P0–P3 已完成此前范围内的验收。工程构建、本地 HTML 页面、HTTPS 来源核验、项目用例迭代与当前交付判断已接入同一持久运行及累计预算。当前个人使用范围为“系统保持运行、允许息屏”，没有声明真实睡眠或息屏测试通过。P6 单任务自主监督 Loop 正在开发，尚未达到阶段门禁。

Supervisor 的需求理解与计划已由模型驱动，P6 自动监督控制器正在集成验收。默认复用本机 Codex CLI 安装及已支持的登录方式，由 Supervisor 管理独立的 `codex app-server` 会话；P4 已实际使用它执行独立定义复核、图像验收和来源核验，P5 已接入需求澄清、计划提案和新会话恢复；P6 已接入自动验收作者、独立复核、验证与同契约修复的控制器，完整真实闭环尚未通过。模型提出结构化方案，控制器核对权限、预算和证据后执行，不能由模型一句“完成”直接放行。它不是本地离线模型或通用模型 HTTP 代理；其他代理端点接入需要单独验证协议。见 [主监督模型与本机 Codex 接入](docs/architecture.md#codex-接入和执行器契约)。

## P5 需求、计划与记忆

新任务先进入需求会话。含糊目标得到具体问题，回答后主控提出事实来源、约束、风格、步骤和可观察的验收项；点击「开始执行」后才准入。主控使用独立只读 Codex 会话，禁止命令、文件修改、联网及额外代理动作；真实环境清单、用户输入、账本与文本记忆由控制器提供。模型输出必须通过结构与语义校验，不以模型自报置信度放行。

需求草稿没有虚构的验收条款或执行节点。澄清、执行和独立验收沿用同一 Run ID 与累计 token 账本；准入将正式契约、顺序执行节点、runtime 与 outbox 一次写入 SQLite。契约保留用户输入的时序、后续修改优先关系，以及验收类型、目标和检查点。P4 独立审查读取完整契约。调用前记录计费意图；途中观察值与可结算终值分开，未知用量保留预留，不能用换会话清零。

项目文本记忆位于 `<workspace>/.supervisor/memory/`，支持项目、模块、子模块层级、来源、任务绑定和失效条件。更新提案通过摘要绑定与版本比较后串行发布，不可变 Markdown 原文和清单用于回溯；SQLite 原生锁仅用于跨进程发布互斥。ContextManifest 记录使用/排除项及原文摘要。当前要求、必要接口、失败原因和账本不能被截断；容量不足会拒绝调用。项目偏好可继承，其他项目与其他任务的接口/失败记录不会混入。直接修改已发布文本会触发完整性错误；需先恢复原版字节，再通过 MemoryStore 提案发布新版本，当前不支持对手改文件直接重建索引。

任务完成部分工作、进入等待验收或暂停且所有调用结算后，可以点击「恢复主控会话」。新的独立主控会话读取持久数据，不自动重跑已有执行。当前采用固定顺序步骤；自主修复、定时监督、模型升级属于 P6，并行调度属于 P7。

CLI 使用 `supervisor goal --data PATH --file REQUEST.json` 提交 `start/answer/admit/restore/cancel`，`supervisor goals --data PATH` 列出需求会话，`supervisor goal-show --data PATH --goal ID` 查看契约和账本。请求结构见 `packages/contracts/p5.ts`。例如：

```json
{
  "type": "start",
  "commandId": "my-project-goal-1",
  "goal": "描述目标、已有条件和期望交付物",
  "workspace": "/absolute/project/path",
  "model": "gpt-5.6-sol",
  "effort": "low",
  "reservation": 100000,
  "timeoutMs": 180000,
  "tokenLimit": 500000,
  "verificationReserve": 100000,
  "maxContextChars": 60000
}
```

`workspace` 可省略，系统在 `~/.supervisor/workspace/` 建立持久暂存目录。模型及思考深度须是本机实际公布的能力。`answer/admit/restore` 要携带当前 `expectedRevision`；同一个 `commandId` 重发不会再次计费。默认每次主控和执行步骤各预留 100,000 token，准入时仍须有足够余额，不会自动扩大总预算。

P5 的范围限制：需求入口暂为文字；验收实现仍使用 P4 的 Node 命令、HTML 交互和 HTTPS 来源能力。生成验收提案不等于独立验收已经通过，自动建立/维护验收器的完整 Loop 留到 P6。未获权威终态的用量保持阻塞，不能无证据重试。文本版本与 SQLite 准入不是跨介质原子事务：极端并发工作区冲突下可能留下尚未适用的未来版本记忆，任务账本不会假准入；任务及契约绑定会排除这些记录，原始需求仍保留在账本。风格记录是有来源的推断偏好，不能改变显式要求或验收标准。

P5 的完整模型链路使用预先声明语法范围的微型 Node 求和项目，验证澄清、准入、真实执行、新上下文恢复、共享预算与独立交付。标本检查器的词法限制只适用于该任务，不能推广为任意 JavaScript 的正确性证明，也不是 Supervisor 对所有项目的限制。另保留原始宽契约下的合法目录读取和局部变量正例，用来检查过窄的验收器是否会被禁止发布；这项拒绝由实际正控制门禁完成，不代表模型能发现所有验收器缺陷。

## P4 独立验证与交付

验收从后台和桌面接入同一控制器：提交项目定义 → 实际正负控制及独立模型复核 → 发布 → 冻结完整清单与候选 → 执行独立验收 → 核对当前交付。没有客户端填写 `passed` 的完成入口；步骤结束仍显示待验收。每次模型调用使用新上下文，复核、UI 和来源验证均计入原 Run 的累计预算。

- **工程：** 独立 Node 检查器读取冻结候选，记录逐条断言与真实退出状态；可声明固定 TypeScript 构建，在独立目录运行真实编译器，逐文件比对待交付二进制的字节和执行权限。同一候选及构建配置在一轮中复用构建证据，参数断言分别执行。
- **UI：** 在实际 Electron 页面填入、点击、观察文本与可见状态，保存每步截图与轨迹，再用真实 Codex 图像能力核对功能、反馈和按钮辨识度。不要求像素匹配；当前只支持冻结候选内的本地 HTML 页面，不等于原生 Android/iOS 验收。
- **资料：** 实际获取 HTTPS 来源，保存完整原文、摘要和获取时间，用原文上下文核验结论。交付前重新抓取比对；查看已交付状态时检查已存证据完整性和时效。当前不是自动选源、搜索和综合研究流程。
- **用例迭代：** 用例修订、原始反例与实现版本不可覆盖。提案通过实际控制和独立语义复核才可发布；替代要保留必要断言、参数和缺陷引用。影响选测可以通过局部检查，不能替代完整交付；在途旧清单不变，新库发布后旧结果不能用于当前交付。
- **证据有效性：** 源码、产物、标准、检查器、工具环境、来源证据变化会使当前交付失效；历史记录保留。同项目的新目标需要自己的契约复核，不能仅凭同一路径、相同版本号借用旧批准。
- **恢复：** SQLite 保存定义、计划、进程意图/身份、用量与结果。验收中断后先停止旧进程并保留原清单；不自动重放模型调用。未确认停止或未知用量仍阻断新写入/派发，不能因重启记为零。

当前仍需用户/调用方提供可执行验收定义，桌面提供六个明确步骤；P5 接入需求与记忆，P6 接入自主提出定义、验收和修复闭环。普通命令检查器被限制为读取冻结候选、只写自身证据，并禁用外部进程及网络；这与摘要核对属于可追溯的防误操作边界，不宣称对同用户恶意篡改具有操作系统级隔离。

环境绑定目前采用保守策略，包含完整 Codex 配置摘要及进程环境；即使某项配置变化不影响本任务，也可能使旧交付失效。当前仅保存环境总摘要，无法从旧记录准确定位首个变化项。历史记录仍保留；已交付 Run 在新环境重新交付需创建新 Run 重新复核和验证，尚未交付的任务可以在原 Run 中重新提出定义和验收；自动分析影响、减少无关失效尚未实现。

可运行定义、严格检查器协议及每步 CLI 示例见 [P4 使用说明](docs/p4-verification.md)。检查器/构建环境缺失、崩溃、超时、缺报告与结论未知分别保留，均不能当作通过。快照显式排除 `.git`、`.supervisor`、`.supervisor-dev`、`node_modules`；保留锁文件、源码和构建输出，目前拒绝符号链接，容量上限 10,000 文件 / 256 MiB。

```sh

pnpm supervisor verification-status --data .supervisor/local --runtime RUNTIME_ID
```

## P3 持久运行与故障恢复

- 监督服务、Worker、Codex 分属独立进程。退出桌面或服务重启保留已在运行的 Worker；Worker 失联时核对真实进程身份及旧写者，不能仅依赖心跳过期接管。

HTTP 步骤要求端点返回 `{ operationId, payloadDigest, result }`。请求携带稳定 `Idempotency-Key` 和正文 SHA-256；查询端点通过 `operationId` 参数返回相同回执。只有实际支持幂等键的端点才能声明 `idempotent:true`，系统不会自动把任意 HTTP API 变成幂等。无回执或回执不匹配保持 unknown；不安全操作即使查询暂时返回 404 也不自动重发。
